# Support you — 病児保育予約サイト

病児保育の予約サイトです。**複数施設の運営を前提**にしており、施設ごとに自治体の実施要綱に合わせたハウスルール（開所日・時間・受付期間・定員・料金・対象年齢など）を設定できます。保護者はスマートフォンから利用登録・申込み・書類（医師連絡票）の提出・予約状況の確認ができ、職員は審査・確定・当日の入退室・休園設定・実績CSV出力ができます。

## 複数施設の考え方

- **本部（オーナー）**：全施設を管理。施設の追加・受付停止、本部管理者の招待。すべての施設で管理者として操作できる。
- **施設の管理者・職員**：招待された施設だけを操作できる。1つのアカウントで複数施設に所属可能（画面上部で施設を切り替え）。
- **保護者**：1つのアカウントで複数施設を利用可能。利用登録・審査・予約・書類は施設ごとに分かれ、他の施設には共有されない。
- **データの分離**：施設ごとに別々の保存単位（集約）を持つため、ある施設の混雑・障害・設定変更が他の施設に影響しない。予約CSV・全データ書き出しも施設単位。
- **ハウスルール**：職員画面「ハウスルール」タブで施設ごとに変更。版番号付きで保存され、変更前の内容は履歴に残る。予約には申込み時のルール版が記録される（CSVの「適用ルール版」）。

Google ドライブの試験版「Support you」（ChatGPT Sites 上の第18版）の業務ロジックを引き継ぎ、実運用できる形（Vercel + Supabase）に作り直したものです。

## 画面

| URL | 用途 |
|---|---|
| `/` | 保護者：施設の一覧（受付中の施設が1つなら自動でその施設へ） |
| `/f/施設ID` | 保護者：その施設のアカウント作成・ログイン、利用登録、申込み、書類提出、履歴、利用案内 |
| `/f/施設ID/line?view=reserve` / `history` / `guide` | その施設のLINE公式アカウントのリッチメニュー用入口 |
| `/staff` | 職員：予約管理、開園日・定員、ハウスルール、CSV出力、職員招待。本部は施設の追加・管理も |
| `/reset` | パスワード再設定（メールのリンクから） |
| `/terms` | 利用規約・個人情報の取扱い |

## ハウスルール（施設ごとに設定。`lib/settings.mjs`）

新しい施設には次の標準値が入ります（試験版の仮ルール）。自治体ごとの要綱に合わせて職員画面から変更してください。

| 項目 | 標準値 | 変更できる内容 |
|---|---|---|
| 開所日 | 月〜金、祝日・年末年始（12/29〜1/3）休園 | 曜日ごと、祝日の扱い、年末年始の期間 |
| 来園・お迎え時刻 | 来園 9:00/9:30/10:00、お迎え 12:00〜17:00 | 任意の時刻の一覧 |
| 受付期間 | 前日12:00〜当日10:00 | 何日前の何時から・まで |
| キャンセル | 当日8:30以降の確定済みは施設確認が必要 | 何日前の何時以降 |
| 定員・保育室 | 1日6名、A室3名・B室3名 | 部屋数・部屋ごとの定員、日ごとの上限 |
| 感染区分 | 呼吸器・消化器・その他、同室は同区分のみ | 区分名、同室制限の有無 |
| 料金（減免前） | 4時間以内1,000円、超過2,000円 | 何段階でも |
| 対象年齢 | 生後6か月〜12歳 | 下限（月齢）・上限（歳） |
| 書類 | 医師連絡票必須、服薬時は与薬依頼書必須 | 与薬依頼書の必須・任意 |
| その他 | キャンセル待ちあり | キャンセル待ちの有無、利用条件文（登録時に同意）、案内文、施設の連絡先・通知先メール |

## 構成

- Next.js 16（App Router）を Vercel で配信
- Supabase：Auth（メール＋パスワード）、PostgreSQL、非公開 Storage（書類）
- ブラウザから Supabase へは直接アクセスしません。すべて `/api/{parent|staff}/{操作}` を通り、サーバーが本人・所属・状態を確認します（`lib/server/api.mjs`）。ログイン情報は HttpOnly Cookie のみに保存します。
- 施設データは1行のJSONを版番号付きで保存（compare-and-swap）し、同時操作でも定員を超えません。終了から45日経った予約は履歴テーブルへ移します。
- メール通知（任意）：Resend。本文に氏名・症状は含めず、日付と状態、サイトへのリンクだけを送ります。

## 公開手順

### 1. Supabase

1. プロジェクトを作成（リージョンは Tokyo 推奨）。
2. SQL Editor で `supabase/migrations/20260923000000_support_you.sql` を実行（テーブル・関数・非公開バケットを作成）。
3. Authentication > URL Configuration
   - Site URL：公開URL（例 `https://support-you.vercel.app`）
   - Redirect URLs：`https://公開URL/auth/confirm`
4. Authentication > Email Templates（リンクをサーバー側で確認する形式に変更）
   - Confirm signup：リンクを `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=email`
   - Reset Password：リンクを `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=recovery`
5. 本番では Authentication > SMTP Settings で独自のメール送信（Resend等）を設定してください。Supabase標準の送信は1時間あたりの件数制限があります。
6. 有料プランでは自動バックアップが有効になります。無料プランの場合は、職員画面「職員・設定 > 全データを書き出す」で定期的に保存してください。

### 2. Vercel

1. このリポジトリを Vercel にインポート（Framework: Next.js）。
2. `.env.example` の項目を Environment Variables に設定。
3. デプロイ後、`/staff` を開き「本部管理者と最初の施設を登録」で `SUPPORTYOU_SETUP_CODE`・最初の施設名・施設ID（例 `yoro`）を入力。
4. 「ハウスルール」タブで、その施設の自治体要綱に合わせてルール・連絡先・通知先メールを設定。
5. 2つ目以降の施設は「本部」タブ →「施設を追加」。追加後に同じくハウスルールを設定。
6. 職員は施設ごとに「職員・設定 > 職員を招待」で招待コードを発行。既に他施設のアカウントを持つ職員は、ログイン後「招待コードで施設を追加」から入力。

### 3. LINE公式アカウント（任意）

施設ごとに、職員画面「職員・設定」の「LINE公式アカウントからの入口」にリッチメニュー用のリンク・画像・設定JSONがあります（リンクは施設ごとに異なります）。

## 公開前の確認事項（施設で決めること）

- 各施設のハウスルールが、その自治体の実施要綱・委託契約と一致しているか
- `/terms` の利用規約・個人情報の取扱いの文面（運営者名・保存期間・問い合わせ先）
- 各施設の電話番号・住所・通知先メール（ハウスルールの「施設の情報」）
- 実データを扱う前に、職員2名・保護者2家庭程度で一連の操作（登録→申込み→書類→確定→入退室）を試すこと

## 開発

```bash
npm install
npm run dev:mock   # Supabaseなしで起動（メモリ上の仮データ・仮ログイン。本番では起動不可）
npm test           # 業務ロジック・API境界の自動テスト
npm run check      # 型検査 + テスト + 本番ビルド
```

`dev:mock` の初期設定コードは `.env.local` の `SUPPORTYOU_SETUP_CODE` で指定します。`SUPPORTYOU_MOCK_NOW=2026-09-24T08:40:00+09:00` のように開始時刻を指定すると、受付時間外でも動作を確認できます。
